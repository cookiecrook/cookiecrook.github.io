aria-actions test cases for w3c/aria#2883

Example 1: actions on the focusable link (not on an ancestor)

aria-actions is on each link, so the actions (Favorite and Delete) work when focus is on the link. The buttons are exposed to assistive technology but aren't in the tab order.

  • ARIA
  • AccName
  • HTML-AAM
  • SVG-AAM

Keyboard shortcuts (when a link has focus)

  • F: Favorite or unfavorite
  • Delete (or Backspace): Delete

Example 2: actions on an ancestor (table row) of the link

aria-actions is assigned on the ancestor <tr>, not on the link. Because focus and the reading cursor land on elements inside the row, like the link, the actions don't work there due to the gap in the spec. The buttons are exposed to assistive technology but aren't in the tab order.

Specifications
Specification Version Latest TR publication Status Actions
ARIA 1.2 6 June 2023 Recommendation
AccName 1.2 21 October 2026 Working Draft
HTML-AAM 1.0 26 October 2026 Working Draft
SVG-AAM 1.0 21 October 2026 Working Draft

Keyboard shortcuts (when focus is on or in a row)

  • F: Favorite or unfavorite
  • Delete (or Backspace): Delete

These shortcuts are page script, so they work anywhere in the row. What's missing on the link and other cell contents is the assistive technology actions from aria-actions.
